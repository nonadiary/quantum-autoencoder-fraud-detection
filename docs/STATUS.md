### 4-1. 양자 큐비트 확장 사용법·주의 (an1.11, 2026-08-02)
- 실행: `python src/run_experiments.py --quantum-scaling 6,8` (또는 `--methods qae_angle@6`). 노트북에서는 `train_quantum_scaled('qae_angle', 6)`.
- 설정: 설정 셀의 `QUANTUM_SCALING_CONFIG`. 회로 코드는 손대지 않고 PCA 차원 + 큐비트 회계 전역만 재바인딩한다(셀 20, 셀 19와 같은 패턴).
- **차원 d별 디바이스 큐비트**: QAE-Angle `d` / DIFE `d` / LS-SWAP `d+3` / Enhanced `2d+5`. → d=4: 4/4/7/13, d=6: 6/6/9/17, d=8: 8/8/11/21.
- ⚠️ **해석상 교란**: 기본 `trash_mode='fixed'`는 trash 큐비트 수를 그대로 두므로 **d가 커질수록 압축률이 낮아진다**. "큐비트↑ → 성능↑"의 일부는 압축 완화 때문이다. 보고서 4.4에서 반드시 명시할 것. 압축률을 유지하려면 `trash_mode='proportional'`.
- ⚠️ **비용 — 아래 수치는 전부 이 노트북(물리 2코어/8GB) 실측이며, 실행 계획상의 기기가 아니다.** 풀런은 [RUNNING_ON_RENTED_CPU.md](RUNNING_ON_RENTED_CPU.md)대로 **대여 고코어 박스(16 vCPU/64GB)** 에서 돌린다. 참고용 1에포크 실측: Enhanced d=4(13큐비트) ~20초, d=6(17큐비트) ~160초, d=8(21큐비트)은 50분 내 미완주로 **중단**(경합 상태에서의 하한값). 21큐비트 상태벡터 33MB에 adjoint 미분 작업사본까지면 8GB에서 빠듯하다 — `enhanced_qvae@6` 잡이 죽은 것도 경합보다 **메모리 압박**이 유력하다. 64GB/16 vCPU에서는 사정이 다르므로 **차원 상한은 박스에서 다시 측정한 뒤 정할 것**(현재 미정).
- 📌 **기존 참고자료**: `results/result_temp.txt`에 **PCA 4~14D 스윕이 이미 완주**되어 있다(11/11 성공, 각 100에포크, 14D=14큐비트가 3226초). 단 이는 **큐비트=차원인 단순 QAE**라 Enhanced(2d+5 큐비트)와 직접 비교되지 않는다 — 제약 변수는 차원이 아니라 **디바이스 큐비트 수**다. 또한 그 기록은 **C2 누수 수정 이전의 단일 실행**이라 인용 불가. 다만 내용은 눈여겨볼 것: **4D가 AUC 0.946으로 최고였고 차원을 올려도 개선되지 않았다**(8D 0.758로 급락, 설명분산은 0.898→0.973으로 계속 상승). 요청②의 결과가 "큐비트를 늘려도 나아지지 않는다"로 나올 가능성.
- `QUANTUM_SCALING_CONFIG['pca_dimensions'] = [6, 8]`은 **잠정값**이다. 기존 4~14D 스윕과 맞출지, 박스 실측 후 조정할지 미결정.

### 4-2. Enhanced qVAE 강화 (an1.12, 2026-08-02)
주인공을 **원천 논문(Araz & Spannowsky, arXiv:2409.04519)이 실제로 쓴 구성**으로 끌어올렸다. 기존 enhanced-qVAE는 '강화 전' 기준선으로 그대로 둔다.

| 강화 항목 | 강화 전 | 강화 후 | 논문 근거 |
|---|---|---|---|
| 얽힘 | 최근접 이웃 고리 CNOT | **strongly entangling layers** (레이어마다 CNOT 사거리 변경 → 모든 쌍 연결) | 논문이 채택한 ref[25]; "CNOT이 각 큐비트를 다른 모든 큐비트와 얽는다" |
| 회전 구성 | RY·RZ (2 파라미터/큐비트) | **YXY** = RY·RX·RY (3 파라미터/큐비트) | Table II 상위 모델 M7~M9가 전부 YXY. 최고 M9 = 재업로딩+교대+L8+YXY |
| 레이어 수 | 4 | **6** | 논문은 L∈{4,6,8}. 2D는 L8 최고이나 신용카드(Table IV)에서는 영향 작음 → 비용 대비 6 |
| (선택) 병렬 임베딩 | 2 (국소 힐베르트 4차원) | 3 | 논문 결론: 2→4차원만으로 큰 개선, "더 넓히면 더 개선될 수 있다". 단 13→17큐비트 |

- 실행: `--methods enhanced_qvae_plus` / ablation은 `--plus-ablation` (또는 `enhanced_qvae_plus:yxy`). 차원 확장과 겹치기: `enhanced_qvae_plus:all@6`. 노트북은 `train_enhanced_qvae_plus()`, `train_enhanced_plus_variant('yxy')`.
- ablation 구성: `base`(=강화 전) / `strong` / `yxy` / `layers6` / `all`(=++) / `par3`. 각 강화 요소의 기여를 분리해 보고서 3.3에 쓸 수 있다.
- 회로 자원(qml.specs 실측, d=4): base 깊이46·게이트132·파라미터64 → `all` 깊이51·게이트244·파라미터144 → `par3` 17큐비트·깊이57·게이트364·파라미터216. **strong은 깊이가 오히려 46→32로 줄어든다**(고리 CNOT 체인이 직렬인 반면 사거리 변형은 병렬화됨) — 연결성은 늘리고 깊이는 줄이는 셈이라 보고서에서 강조할 만하다.
- 기본 전역값(`QVAE_ROTATIONS`/`QVAE_ENTANGLEMENT`/`QVAE_PARAMS_PER_QUBIT`)은 **강화 전 동작을 그대로 재현**하도록 두었다. 강화는 전역 재바인딩으로만 적용된다(셀 19·20과 같은 패턴). 검증: `enhanced_qvae_plus:base`와 `enhanced_qvae`가 같은 시드에서 G-Mean·AUC가 완전히 일치(0.6047 / 0.6066).
- ⚠️ **훈련 예산 주의**: `all`은 파라미터가 64→144(2.25배)인데 에포크는 100으로 고정이다. 고정 에포크는 빨리 수렴하는 작은 모델에 유리하므로, 풀런에서 ++가 base보다 낮게 나오면 **"강화가 실패했다"로 바로 결론짓지 말고 학습곡선(수렴 여부)부터 확인**할 것. 필요하면 ++에만 에포크를 늘리되 그 사실을 보고서에 명시한다.
- **par3 비용**: 1에포크 486초(17큐비트×6레이어) — **이 노트북 실측**이므로 §4-1의 단서가 똑같이 적용된다. 풀런 포함 여부는 박스에서 재측정 후 결정.
